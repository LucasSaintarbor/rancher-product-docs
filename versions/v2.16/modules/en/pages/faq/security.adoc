[#_how_does_rancher_verify_communication_with_downstream_clusters_and_what_are_some_associated_security_concerns]
== How does Rancher verify communication with downstream clusters, and what are some associated security concerns?

Communication between the Rancher server and downstream clusters is performed through agents. {rancher-product-name} uses either a registered certificate authority (CA) bundle or the local trust store to verify communication between {rancher-product-name} agents and the {rancher-product-name} server. Using a CA bundle for verification is more strict, as only the certificates based on that bundle are trusted. If TLS verification for a explicit CA bundle fails, Rancher may fall back to using the local trust store for verifying future communication. Any CA within the local trust store can then be used to generate a valid certificate.

As described in https://www.suse.com/c/rancher-security-update/[Rancher Security Update CVE-2024-22030], under a narrow set of circumstances, malicious actors can take over Rancher nodes by exploiting the behavior of Rancher CAs. For the attack to succeed, the malicious actor must generate a valid certificate from either a valid CA in the targeted Rancher server, or from a valid registered CA. The attacker also needs to either hijack or spoof the Rancher server-url as a preliminary step. {rancher-product-name} is currently evaluating {rancher-product-name} CA behavior to mitigate against this and any similar avenues of attack.
