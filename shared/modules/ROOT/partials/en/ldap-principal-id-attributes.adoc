By default, Rancher uses the Distinguished Name (DN) of a directory entry as the ID of the user or group principal. The DN changes when you move or rename the entry. Rancher then treats the entry as a new principal, and the permissions assigned to the old principal no longer apply.

To keep principal IDs stable, set the *User Identifier Attribute* and *Group Identifier Attribute* fields in the *Customize Schema* section. Rancher then uses the value of the attribute as the principal ID instead of the DN. For example, use `sAMAccountName` in Active Directory, or `uid` for users in OpenLDAP and FreeIPA. Leave a field empty to keep using the DN.

Choose attributes that meet the following requirements:

* The value is unique across all users, or across all groups.
* The value stays the same when the entry moves to another part of the directory.
* Every user and group entry has the attribute. Login fails for a user whose entry lacks the user identifier attribute.

Both fields must be valid LDAP attribute names.

[IMPORTANT]
====
You can't change the identifier attributes while the provider is enabled. To change them, disable the provider, change the attributes and enable the provider again.

When you disable the provider, Rancher deletes the users, bindings and other resources of the provider by default. After you enable the provider again, users get new principal IDs when they log in, and you must assign their permissions again. For more information, see {xref-authn-authz}#_disabling_an_auth_provider[Disabling an auth provider].

If the provider has the `management.cattle.io/auth-provider-cleanup: user-locked` annotation, Rancher keeps the users and bindings. They keep the old principal IDs, which no longer match any user or group after the change.
